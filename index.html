How it works

Kiwix compresses whole websites into .zim files; a tiny bundled server reads them in your browser. The script assembles the archives and the reader onto one stick — no hotspot, server or hosting.

Build once

Run the script on a Linux or Mac to fill an exFAT stick with the libraries and the reader.

Plug in anywhere

Carry the stick to any Windows, Mac or Linux computer. Nothing to install.

Browse offline

Double-click one launcher; the whole library opens at localhost:8888.

Build it

On a Linux or macOS machine with bash curl aria2 tar unzip and a 256 GB+ USB stick. The download is ~180 GB and fully resumable.

# 1. Format the stick exFAT — this ERASES it, triple-check the device name
lsblk -o NAME,SIZE,TRAN,MODEL        # find YOUR stick (TRAN=usb), e.g. sdb
sudo umount /dev/sdX?* 2>/dev/null
sudo wipefs -a /dev/sdX
sudo mkfs.exfat -n PUNKNUKE /dev/sdX

# 2. Mount it, then build (mount path varies by OS/distro)
bash make-usb-library.sh /run/media/$USER/PUNKNUKE
FAT32 can't hold the ~119 GB Wikipedia file, so exFAT is required. Stop with Ctrl+C and re-run any time — finished files are skipped, partial ones resume.

Use it

Plug the stick into any computer and open the launcher for that OS. Your browser opens at http://localhost:8888.

Operating systemWhat to open

First run may show a security prompt (SmartScreen / Gatekeeper) — allow it; these are unsigned open-source binaries run from a stick.

FAQ

Does it need the internet to read?

No. Once built, the stick is fully self-contained and works with no network, no account and no installed software.

Can I make it smaller?

Yes — set WIKIPEDIA_FLAVOR=nopic (no images, ~85 GB smaller) or mini (intros only). You can also trim the CONTENT list.

Why does the stick mount at a different path each time?

That's normal. The launchers locate themselves relative to the stick, so it doesn't matter — only the one-time build step needs the current mount path.

A download stalls at 0 B/s — is it broken?

No, just a dead Kiwix mirror. The script drops slow connections and retries others automatically. Let it run, or re-run to resume.

The viewer says "unable to add" a file.

That archive is corrupt or incomplete. Delete that one .zim and re-run the script to re-fetch it.
